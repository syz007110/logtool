# HTTP API 设计规范

## 1. 适用范围

- 本规范适用于所有新增或修改的 `/api/` HTTP 接口。
- 历史接口不要求一次性重构；新增能力应遵循本规范，并在有明确改造计划时逐步迁移旧接口。
- OpenAPI 文档是 HTTP API 的唯一契约来源；实现、前端调用与测试必须与其保持一致。
- 开发环境可通过 `/api/docs` 阅读 Swagger UI，并从 `/api/openapi/openapi.yaml` 加载契约；生产环境默认不暴露，只有设置 `ENABLE_API_DOCS=true` 才启用。

## 2. 路径与 HTTP 方法

- 所有接口使用 `/api` 作为基础前缀。
- 资源路径使用复数和 kebab-case，例如 `/api/audit-logs`。
- `GET` 用于读取；`POST` 用于创建；`PUT` 用于完整更新；`PATCH` 用于部分更新；`DELETE` 用于删除。
- 非 CRUD 的明确动作可使用子路径，例如 `POST /api/audit-logs/export`；路径中的动作名使用 kebab-case。
- 不对后端内部模块调用提供 HTTP 接口；例如审计写入仅通过后端 `AuditService` 调用。

## 3. 数据格式

- 请求与响应体使用 JSON，字段名使用 camelCase。
- 数据库可使用 snake_case，但不得直接作为 HTTP 响应字段。
- 时间统一使用 UTC ISO 8601 字符串，例如 `2026-11-02T06:00:00.000Z`。
- 对外 ID 使用字符串，避免 JavaScript 数值精度问题。
- 枚举使用后端维护的稳定代码；不得依赖前端展示文本作为业务判断。

## 4. 查询、分页与排序

- 查询条件使用 query 参数；复杂或敏感查询条件使用请求体时，必须在 OpenAPI 中说明原因。
- 分页参数统一为 `page`、`limit`；两者均为正整数。
- 列表接口统一返回：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "limit": 20
}
```

- 每个列表接口必须声明默认排序。审计日志默认按 `occurredAt DESC` 排序。
- 筛选参数的匹配方式（精确、前缀或模糊）必须在 OpenAPI 中明确。

## 5. 鉴权与权限

- 受保护接口使用 Bearer Token 鉴权。
- 每个受保护接口必须声明所需权限；权限码由后端维护。
- OpenAPI 使用 `security` 声明鉴权，并使用 `x-required-permission` 标记业务权限。
- 401 表示未认证，403 表示已认证但权限不足。

## 6. 响应与错误

- 成功响应直接返回资源对象、列表分页对象或文件流；不额外嵌套无业务价值的 `data` 包装。
- 错误响应统一为：

```json
{
  "code": "AUDIT_EXPORT_LIMIT_EXCEEDED",
  "message": "导出记录数超过允许上限",
  "requestId": "req_01K..."
}
```

- HTTP 状态码使用：400（参数错误）、401（未认证）、403（无权限）、404（资源不存在）、409（状态冲突）、422（业务规则不满足）、500（系统错误）。
- 错误响应不得包含密码、Token、验证码、授权码、堆栈或内部敏感信息。

## 7. 导出与异步任务

- 导出接口必须声明文件格式、编码、最大导出量、权限和失败行为。
- 不允许静默截断导出结果；超出上限时返回明确业务错误。
- 执行时间较长的任务应创建异步任务并返回任务 ID，而非长时间阻塞 HTTP 请求。
- 需要审计的导出、下载或高风险操作，应在成功后写入相应审计事件。

## 8. 版本与兼容性

- 同一主版本内仅允许向后兼容变更，例如新增可选字段或新增可选筛选条件。
- 删除字段、改变字段语义、改变权限、改变分页行为或修改已有枚举含义，必须通过 `/api/v2/...` 等新版本接口发布。
- 废弃接口应在 OpenAPI 标记 `deprecated: true`，并记录替代接口与迁移期限。

## 9. 交付要求

- 新增或修改 HTTP API 时，必须在同一变更中更新 OpenAPI、后端实现和接口测试。
- API 设计评审至少确认：资源边界、权限、输入校验、错误码、兼容性、敏感数据和审计要求。


| 场景            | 设计方式                           | 是否写 OpenAPI  |
| ------------- | ------------------------------ | ------------ |
| 前端、移动端、外部系统调用 | HTTP API                       | 是            |
| 后端业务模块调用审计能力  | Service 模块接口                   | 否            |
| 数据库读写         | Repository / Model / Migration | 否            |
| 队列任务、异步消息     | Job / Event 契约                 | 视是否跨进程或跨服务而定 |
