# 移动端需求

- 桌面与移动端共用逻辑层（状态、API、多语言）。
- 移动端通过 PWA 增强离线访问、缓存、安装体验。
- 所有数据接口共用后端（Node.js + MySQL / PostgreSQL / Redis）。
- 支持iOS Safari 、Android端主流的浏览器软件

## 移动端前端的技术栈

| 分类 | 技术/库 | 说明 |

2. 技术实现要求
- Service Worker 配置：采用 Workbox，实现三种缓存策略
  - Cache First：用于静态资源（Vant UI组件库、图标、字体等）
  - Network First：用于 API 接口数据，失败时回退到缓存
  - Stale While Revalidate：用于 i18n 语言包，优先使用缓存，后台更新
- IndexedDB 离线存储：使用本地数据库存储故障码数据和搜索历史
  - error_codes_cache：故障码缓存

  - recent_searches：最近搜索记录

  - log_entries_cache：日志条目缓存

- Manifest.json：配置应用图标、主题色、启动画面、显示模式

## 适配问题

### 问题描述

移动端 PWA 在浏览器页面显示正常，固定到主屏幕后，本应被浏览器底部操作栏覆盖的区域变成了空白，留白较多。

这是 PWA 全屏显示模式（standalone/fullscreen）与浏览器可视窗口安全区（Safe Area）不匹配造成的，在 iOS Safari（iPhone X 及以后机型）上尤为常见。

### 原因分析

**浏览器模式（有地址栏）**：页面被包裹在浏览器窗口内，浏览器 UI（地址栏/底部操作栏）会自动遮挡页面一部分，浏览器会自动调整 viewport 高度减去这些栏位。

**安装到主屏幕后（独立 Web App 模式）**：页面以 display: standalone 或 fullscreen 模式运行，不再有浏览器地址栏/工具栏，但浏览器的安全区 padding 仍然存在（特别是底部的 Home 指示条区域）。如果页面布局写死了 100vh，则会多出底部安全区留白。

**根本原因**：在 iOS Safari 的 PWA 模式中，100vh 不等于真实可视区域高度。Safari 会把整个屏幕高度算作 100vh，而不是除去安全区和 Home Indicator 之后的有效区域。

### 典型症状

| 模式 | 现象 |
| --- | --- |
| Safari 浏览器访问 | 正常显示，底部留白被地址栏覆盖 |
| PWA 安装启动 | 页面下方留出空白（约 20~40px） |
| 部分机型（刘海屏、全面屏） | 上下都有空白区域，视觉不居中 |

### 解决方案

#### 方案 1：使用安全区（Safe Area Insets）变量

现代移动浏览器（iOS Safari/Chrome）支持以下 CSS 环境变量：

- `env(safe-area-inset-top)`
- `env(safe-area-inset-bottom)`
- `env(safe-area-inset-left)`
- `env(safe-area-inset-right)`

应用方式如下：

```css
html, body {
  margin: 0;
  height: 100%;
  background: #fff;
  padding-bottom: env(safe-area-inset-bottom);
  padding-top: env(safe-area-inset-top);
}
```

效果：浏览器自动计算底部安全区高度，不会在 PWA 模式下出现多余留白，在普通浏览器访问时无影响。

#### 方案 2：避免使用固定 100vh

在移动端 PWA 中，推荐改为：

```css
.main-container {
  min-height: 100dvh; /* 动态视口单位，支持 iOS 16+ */
}
```

说明：
- 100vh 固定为设备屏幕高度
- 100dvh（Dynamic Viewport Height）会动态计算实际可视区域高度，不受地址栏、底部栏影响
- Chrome、Safari（iOS 16+）均已支持

#### 方案 3：在 manifest.json 中正确声明显示模式

```json
{
  "display": "standalone",
  "orientation": "portrait",
  "background_color": "#ffffff",
  "theme_color": "#3b82f6"
}
```

fullscreen 模式虽然能消除浏览器 UI，但更容易触发安全区计算错误，建议保持 standalone。

#### 方案 4：针对 iOS 加上安全区 meta 标签

```html
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

- `viewport-fit=cover` 允许页面扩展到安全区外
- `black-translucent` 让状态栏透明，页面可延伸至顶部
- `apple-mobile-web-app-capable` 开启独立 Web App 模式

#### 方案 5：底部安全区内使用背景或渐变填充

如果页面底部有固定元素（如悬浮搜索按钮/TabBar），建议利用 `env(safe-area-inset-bottom)` 适配：

```css
.bottom-bar {
  position: fixed;
  bottom: 0;
  width: 100%;
  background: #fff;
  padding-bottom: env(safe-area-inset-bottom);
}
```

这样即使在有底部 Home 指示条的设备上，也不会让按钮被遮住或产生空白。

#### 推荐综合方案（PWA + Vue + 移动端）

1. 在 index.html 中加入：

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

2. 使用 CSS：

```css
html, body {
  margin: 0;
  height: 100%;
  background: #fff;
  padding-bottom: env(safe-area-inset-bottom);
}

.app-container {
  min-height: 100dvh;
  display: flex;
  flex-direction: column;
}
```

3. Vue 页面底部按钮：

```css
.floating-button {
  position: fixed;
  right: 16px;
  bottom: calc(16px + env(safe-area-inset-bottom));
}
```

### 对 Android 的影响

Android 上的 PWA 基本不会出现 iOS 那种底部留白问题，但也有自己的显示差异点（主要与 Chrome 和系统导航栏相关）。

#### Android vs iOS 对比

| 对比项 | iOS (Safari/WKWebView) | Android (Chrome/WebView) |
| --- | --- | --- |
| 浏览器 UI 占用 | 地址栏/底部操作栏 | 顶部地址栏可隐藏，底部操作栏较小 |
| PWA 显示模式 | standalone/fullscreen | standalone/fullscreen |
| Safe Area 安全区 | 有（刘海 + 底部 Home 指示条） | 通常无安全区，仅部分机型有圆角或导航手势区域 |
| env(safe-area-inset-bottom) 支持 | 有效（必须加） | 支持，但通常返回 0 |
| 100vh 显示差异 | 有误差（含状态栏） | Chrome 已修复，可用 |
| 100dvh 支持 | iOS 16+ | Chrome 108+ |
| 常见留白问题 | 底部空出 Home 指示条高度 | 几乎无影响 |

#### Android 下的典型显示逻辑

PWA 添加到 Android 主屏幕后：
- Chrome 启动 Web App Shell，地址栏、底部工具栏全部消失
- 页面在全屏下运行，默认 `viewport-fit=cover` 行为生效
- 系统导航条不影响网页内容布局
- 绝大多数机型底部安全区高度为 0，`env(safe-area-inset-bottom)` 也返回 0

因此不会出现 iOS 那种"底部留白 20~40px"的问题。

#### 仍建议加上安全区自适应代码

Android 厂商多样化（尤其国内机型，如华为、小米的导航手势区域有时会影响布局），推荐保留统一安全区处理逻辑：

```css
html, body {
  height: 100%;
  padding-bottom: env(safe-area-inset-bottom, 0);
  padding-top: env(safe-area-inset-top, 0);
}

.app-container {
  min-height: 100dvh;
}
```

Android 下 `env(...)` 返回 0，不影响布局；iOS 下返回安全区像素，自动补齐留白。完美兼容双平台。

#### Android 下的可能差异及调整建议

| 现象 | 说明 | 解决方式 |
| --- | --- | --- |
| 页面突然”跳动” | Chrome 地址栏自动隐藏后 viewport 高度变化 | 使用 100dvh 替代 100vh |
| 顶部状态栏颜色不统一 | 主题色未设置 | 在 manifest.json 加 `theme_color` |
| 导航栏按钮遮住底部按钮（少见） | 个别机型系统问题 | 可用 `env(safe-area-inset-bottom)` 兜底 |

### 跨平台最优方案汇总

| 项目 | 推荐设置 | 原因 |
| --- | --- | --- |
| meta viewport | `content=”width=device-width, initial-scale=1, viewport-fit=cover”` | 开启安全区计算 |
| 高度单位 | 100dvh 替代 100vh | 防止高度计算误差 |
| 底部安全区 | `padding-bottom: env(safe-area-inset-bottom, 0)` | iOS 有效，Android 无影响 |
| 显示模式 | `”display”: “standalone”` | 避免 Safari 留白现象 |
| 主题色 | `”theme_color”: “#3b82f6”` | 控制 Android 状态栏颜色 |
| 背景色 | `”background_color”: “#ffffff”` | 控制启动页背景 |
| CSS 调整 | 避免固定绝对值布局 | 兼容多机型 |

### 总结

PWA 从浏览器添加到主屏幕后底部留白，是因为系统为 Home 指示条保留了安全区。

解决方式：
- 使用 `viewport-fit=cover`
- 使用 `env(safe-area-inset-bottom)`
- 避免死用 100vh，改用 100dvh
- 在底部元素中加上安全区 padding

跨平台最佳实践：
- HTML 中加上 `viewport-fit=cover`
- 使用 100dvh
- 保留 `env(safe-area-inset-bottom)`

这样可以在所有机型上保证无留白、无遮挡、全屏自适应。
