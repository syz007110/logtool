# 手术数据分析

- 当前是在批量日志分析页面中点击手术统计后计算日志批量分析中所有日志条目中包含几场手术信息，每一场手术单独做统计计算，统计过程遍历每一条日志进行不同事件的判断；
- 列举一些难以处理的场景，一场手术没有手术结束时间，？？？？
- 计算统计可以通过逐条处理获取到的日志记录，根据每条日志的故障码（errCode）及其对应的参数（p1、p2、p3、p4）进行不同分支判断，具体处理过程根据[日志读取过程流程图](https://app.notion.com/p/259cc02ebc29801e8c8ccc4e749bbd2c?pvs=21)
    - 开机事件、关机事件、手术开始、手术结束、连台手术需要记录上一场手术结束
    - 器械相关信息记录：器械类型、udi码、使用时间
    开机事件、关机事件、手术开始、手术结束、连台手术需要记录上一场手术结束
    - 器械相关事件：器械类型、udi码（）、器械寿命、使用时间；
    - 器械安装流程是0->1->2->3->4，器械状态跳转到4代表器械安装，此时读取到udi码，但还未识别到器械类型，此时应该打开器械udi记录窗口（等待8s内的日志）等待器械类型更新，获取到器械类型才把udi码拼接写入该器械；保留2C2D的
    - 器械状态，500e是记录器械状态变化定义：
    -"0": "隔离板未安装", "1": "隔离板自检","2": "隔离板自检完成","3": "芯片校验","4": "芯片校验完成","5": "器械自检","6": "器械自检完成","7": "器械拔下","8": "器械拔下完成"
    - 故障码后4位500e，p1对应臂号，p3当前状态，识别到500e更新器械状态
    - 器械安装和拔下事件：
    - 器械安装：p2 != 4 且 p3=4
    - 器械拆下：p2 != 7 且 p3=7
    - 器械UDI码，通过510e 记录普通器械的UDI码、581e超声刀的udi码、584e兼容旧器械的UDI码；
    - 器械类型：故障码后4位510e，p1对应臂号，p3为器械类型，识别到510e更新器械类型；
    - 器械寿命：故障码后4位502E，对应的errCode.charAt(1)-3得到，作为 0–3 的臂索引，对应 1–4 号臂，p2当前的器械寿命，识别到502e需要更新器械寿命；
    - 器械总使用时间：故障码后4位50EE，对应的errCode.charAt(1)-3得到，作为 0–3 的臂索引，对应 1–4 号臂，p3当前的器械寿命，p1总使用时间的小时，p2总使用时间的分钟；p3可以做外器械寿命事件的补充，如果触发50ee时，器械寿命未更新过，可以使用p3更新器械寿命
    - 需要处理器械超出使用次数2C2D，重置器械类型，不识别udi码
    
    - 故障统计：统计手术过程触发安全报警的次数和具体的报警信息，日志条目中以A\B结尾的故障码认为触发了安全报警，解除恢复过判定为“已处理”，未解除恢复判断”未处理“，对于故障进行去重操作，对于未处理的故障，在解除恢复前只统计一次；
    - 网络统计：若本场手术是远程手术，则需要统计本场手术的网络延时,远程手术判断条件：出现过故障码结尾是416d的日志且p1=1，网络延时=405e 中 p3的值；
    - 记录手术过程中状态机变化，记录变化的时间戳和状态机值 故障码后四位310e，状态机值=p2
    - 记录“内窥镜脚踏触发的次数”，故障码后四位=705E 或 故障码后四位=526E，当参数1由0变为1，再由1变为0，记作1次，两个故障码需要独立统计，但2s内如果同时出现，则只统计705E,此数据统计至surgeries数据中structured_data字段/surgery_stats/endoscope_pedal中
    - 记录“臂切换脚踏触发的次数”，故障码后四位=704E 或 故障码后四位=527E，当参数1由0变为1，再由1变为0，记作1次，两个故障码需要独立统计，但2s内如果同时出现，则只统计704E，此数据统计至surgeries数据中structured_data字段/surgery_stats/arm_switch_count中
    - 记录“左手离合触发的次数”，故障码后四位=70AE 且 参数3 = 1；当参数1由0变为1，再由1变为0，记作1次，此数据统计至surgeries数据中structured_data字段/surgery_stats/left_hand_clutch中
    - 记录“右手离合触发的次数”，故障码后四位=70AE 且 参数3 = 2；当参数1由0变为1，再由1变为0，记作1次，此数据统计至surgeries数据中structured_data字段/surgery_stats/right_hand_clutch中
    - 记录“脚离合触发的次数”，故障码后四位=706E 或 故障码后四位=525E，当参数1由0变为1，再由1变为0，记作1次，两个故障码需要独立统计，但2s内如果同时出现525E和706E，则只统计706E，此数据统计至surgeries数据中structured_data字段/surgery_stats/foot_clutch中
    - 特殊情况处理：
        1. 无器械时，器械类型=0
        对于器械类型 = 9，10，11，23，24时，可能会发生器械类型再次该改变（由于器械类型会从图像再次获得），若出现从器械类型转换为其他器械类型（9，10，11，23，24），则认为从图像主机获取到到器械类型，并不代表更换了器械，UDI码不改变，器械类型需要跟着改变，器械使用时间怎么统计比较好，
        2. 需要处理器械超出使用次数

✅ 总结：

- 页面核心是「**表格风格的时间轴**」，推荐用 **ECharts custom series** 实现，能保证和你截图的效果几乎完全一致。
- 下方折线图、表格部分用 ECharts + Element Plus 直接实现即可。
- 最终的结构化数据来源于数据库 `surgeries.structured_data`，目前阶段可以先用手工 mock 数据。

- 前端显示每场手术需要写入surgeries 表的内容包括结构化数据`surgeries.structured_data`
- 设有保存按钮，将surgeries数据保存到数据库
- 手术id生成规则：设备编号-手术开始时间（YYYYMMDDHHMM）；
- 点击保存按钮：系统生成一个新的`surgery_versions` 版本。对比新版本与 `surgeries` 当前数据：
    - 如果一致：直接覆盖或忽略。
    - 如果不一致：
        1. 弹窗提示“检测到手术数据变化”
        2. 在弹窗中用可视化方式展示差异（例如表格高亮变化字段、时间轴对比器械使用或臂动作）
        3. 用户确认是否替换当前版本：
        - 确认：将 `surgeries.structured_data` 更新为新版本，并记录 `surgery_versions`
        - 取消：保留原版本不变

`surgeries.structured_data` 始终保存**用户确认后的最新版本**。

`surgery_versions` 保存所有生成的版本（未确认或历史版本），用于对比和回溯。
